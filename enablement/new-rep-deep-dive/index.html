What OrcaRouter actually is

One OpenAI-compatible endpoint in front of a few hundred models. It decides, per request, which model serves it, and it governs what an agent is allowed to do while it runs. That is the whole product. Everything below is detail on those two sentences.

What it is

An adaptive model-routing inference gateway. You point your existing OpenAI client at our base URL, set the model to orcarouter/auto, and carry on. Requests keep the same shape they had before. What changes is that something now decides which model answers each one, instead of the model being hardcoded in your application months ago and never revisited.

Technically A reverse proxy in front of many upstream providers, holding one set of credentials, applying workspace-scoped policy at several points in the request lifecycle, and returning standard OpenAI-compatible response objects plus X-Orca-* headers.
In plain words Your app talks to one door instead of a dozen. Behind that door, someone chooses the right model for each request, watches what the agent tries to do, and writes down what it cost.

Route

Pick the model per request. Cheapest, best quality, or balanced. You stop hardcoding one vendor.

Observe

Per-request cost, resolved model, latency and token counts, so spend becomes attributable.

Govern

Guardrails on content, a firewall on agent actions, evidence you can hand an auditor.

Why the category exists

Three things went wrong at once for teams shipping AI features, and each one is a separate reason someone takes this meeting.

1. The model you picked is now wrong

A new model lands cheaper or better every few weeks. If the model name is a string in your codebase, switching costs a deploy and a review cycle, so it does not happen. Teams end up paying for last quarter's decision.

2. One vendor is a single point of failure

Rate limits and outages arrive without warning. Handling that inside the application means every team writes its own retry, backoff and fallback logic, badly, in a different repository.

3. Nobody can say what it cost

Inference lands in cost of revenue or on a card statement with no per-call attribution. Finance asks which feature is expensive and the honest answer is that nobody knows.

Add a fourth once agents reach production: an agent can call tools, so it can also delete a database or post a secret to an outbound URL. That is a policy problem, and it is the part of this market that is least crowded.

How it works

The tabs below are the part new reps get asked about first. Read the flow once, keep the jargon decoder open in a second tab during your first calls.

One request walks these six layers in this order. Each layer is workspace-scoped, attaches to an API key, and needs no code change. Step through them and watch the cost line, because only one of the six ever bills.

1. Scoped API key

TechnicallyModel allowlists, spend limits, and IP restrictions, evaluated before anything else runs.
In plain wordsThe key decides what this caller is even allowed to ask for.
no model spend

2. Input guardrails

TechnicallyContent screening on the prompt. A block returns HTTP 400 guardrail_blocked and the quota is not charged. A mask redacts the text and lets it continue.
In plain wordsChecks the words going in, before you pay a model to read them.
a block here bills nothing

3. The model runs

TechnicallyRouting picks the serving model, unless the caller named one explicitly, in which case routing steps aside.
In plain wordsThe actual work happens here. If you are looking for the line item on the invoice, this is it.
the only layer that bills

4. Agent firewall

TechnicallyGrades tool calls, MCP dispatch and outbound hosts before they execute. Verdicts: allow, audit, deny, sanitize, pending approval, cap cost.
In plain wordsChecks what the agent is about to do, not what it said.

The honest nuance: the model has already run by this point, so an enforcing verdict here cannot refund that call. Where it saves real money is inbound: a denied tool surface never reaches the model at all, so that costs no tokens.

spend already incurred

5. Output guardrails

TechnicallyScreening on the response before it returns to the caller.
In plain wordsChecks the words coming back out.
spend already incurred

6. Audit

TechnicallyRuns alongside layers 2 to 5, correlated to the agent run and the session.
In plain wordsWrites the record that makes the other five layers provable later.
no extra cost

They askYou answer
Does routing add latency?The routing decision itself is small. The honest frame is that we add a hop, and the failover and cache behavior usually wins it back. Measure it on their traffic rather than quoting ours.
What happens if a provider dies mid-stream?Failover lands before the first byte. Once bytes are flowing, a mid-stream drop is not transparently retried. Say this before they find it in staging.
Will routing change my outputs?Yes, if you let it choose. Name a model explicitly and routing steps aside entirely, which is the answer for anyone who needs determinism.
How do you pick the cheapest model safely?A learned strategy needs about ten observations before it starts steering, and it degrades to a balanced default rather than failing.
Can I keep my own provider contract?Yes, BYOK. Note there may be a platform fee on BYOK traffic, and we show you the exact rate in the console.
Do you store our prompts?No, by default. Request-body logging is opt-in and off. Some metadata is kept, and the retention windows differ by data class, so answer with the specific one rather than saying "we keep nothing".
Do your guardrails block before we pay?A block at input returns before the model runs and does not charge quota.
Does sanitize clean tool results too?No. Sanitize cleans tool-call arguments, not what a tool returns. This is the most common misconception in this space and the docs say so themselves.
Can we run everything in shadow first?The firewall has shadow mode. Guardrails do not, they either fire or they do not. Do not promise a blanket shadow rollout.
Will routing escalate us to expensive models without asking?Not by default. Escalation ships off, and it only ever applies to router traffic. A model you name directly is never escalated.
What are your rate limits?Workspace-scoped, and reactive: a 429 with Retry-After. We do not publish a remaining-budget header, so do not promise predictive limits.
Is the free model the same as the paid one?Same weights, its own limits. The suffix is the gate: dropping -free does not fail, it bills.

What we ship, in routing terms

One endpoint, many models

Point base_url at our v1 URL and set the model to orcarouter/auto. Naming a model explicitly bypasses routing, which is a feature, not a gap.

X-Orca-Resolved-Model tells you what actually served it

Named routers

Your own routing policies with allowed-model globs, a default safety net, and a strategy: cheapest, quality, balanced, or adaptive.

balanced is the default for a user-created router

Fusion

A curated panel answers in parallel and a judge returns the single strongest complete answer. Never a blend. You always get one real model's full response.

billed as the sum of the underlying completions, at cost

Fallback chains

Up to five models in order. Fails over on an upstream error. Fails only when every entry is exhausted, and it never quietly drops into free capacity.

fails over before the first byte

Frontier escalation

A tier, not a second router. Off by default, then manual or automatic on difficulty and failure signals. The base tier removes the strong pool from candidates entirely.

router traffic only

Session affinity

Keeps a conversation on one model so the prompt cache stays warm. The window you get depends on the identifier you send, and pins are soft, never enforced when wrong.

5 minutes by default, far longer with a session header

Two marketing angles fall out of this, and both are checkable rather than rhetorical. Fusion is frontier-class output at cost with a judge as the mechanism, so the claim can be inspected. Escalation is the other half: pay frontier prices only when the work actually needs it.

How the money works

Tokens are pass-through. We bill the provider's published price and add nothing to it. The routing fee column reads $0.00 on every model. Revenue comes from plans, not from marking up model spend.

Plans change features, not token price

PlanWhat it isWhere the zero fee applies

TeamAround $49 per month, up to 10 seats, adds compliance enforcement and reportingYes
Custom / EnterpriseUnlimited seats, dedicated infrastructure, 99.99% SLA, priority access to new modelsNo. Quoted individually, possibly with a volume-tier routing fee.
Where the zero fee stops The $0.00 routing fee covers Free and Team. BYOK traffic may carry a platform fee, and the docs default is 5% (configurable, and shown in the console). Enterprise is quoted individually. Never carry the "we add nothing" line into a BYOK or Enterprise conversation. The first quote makes it false, and that is how a warm deal goes cold.

Three ways to pay

Top up a balance, take a credit subscription that refills each period, or bring your own provider key. Larger subscription plans carry bonus credit.

Caching is the real lever

Cached input bills at the provider's cache rate, and keeping a conversation on one model is what keeps the cache warm. This is the honest mechanism behind most savings.

Free models are a trial lane

Ids end in -free and run under their own limits. The tier is laddered by lifetime spend, not by plan, and the lowest rung has a per-request prompt cap.

Refunds

A top-up refund keeps a 10% fee. Know this before someone asks, and never promise a fee-free refund.

Internal only, do not put in writing to a prospect Deals at the top end are a minimum committed spend, prepaid monthly as credit. It is a floor on spend that already routes through us, never a fee on top. The ratio is one number: commit percent equals 100 minus savings percent. Promise a 40% cut and the commit sits at 60% of what they spend today. Never present a savings figure without its matching commit. Get the user's sign-off before quoting this motion to anyone.

Who buys it, and what they care about

Platform or infrastructure engineer

Cares about failover, latency, one endpoint, and not maintaining retry logic in every service.

Discovery: how many providers does your code talk to today?

Head of AI or VP Engineering

Cares about shipping faster without a re-platform every time a model launches or retires.

Discovery: who decides which model a feature uses, and how long does that take?

FinOps or finance

Cares about attribution. Which feature, which team, which customer, and can the number be defended.

Discovery: can you tell me what AI cost per feature last month?

CISO or security

Cares about evidence, residency, access control, and what an agent is allowed to touch.

Discovery: what stops an agent from reaching an internal host today?

Two notes on who to skip. Pure GTM, legal, finance-ops and executive assistant titles rarely own this decision, so they are noise on a list. And companies whose own product is a gateway or router are competitors or partners, never prospects.

"Here is our SOC 2 Type II report"
What it meansWhat exists is a one-page certificate from a certification body, not a report from a licensed audit firm.

Practice

Reading this page is not the same as surviving a call. Two exercises, both scored, both drawn from objections and lines that have actually come up. Pick your answer, then read why the other options are worse. That second part is the useful bit.

Drill 1: what do you say?

One answer per objection, scored on the first pick. Every option gets feedback once you choose, including the ones you did not pick.

1. "We already route models ourselves. What does yours add that our own code doesn't?"

2. "So the routing fee is zero. What is the catch?"

3. "Prove you are better than what we use. Where do you rank?"

4. "We cannot put anything in the request path until security signs off."

5. "Can you do better on price? We need a discount to move on this."

6. "When we mask sensitive data, does it also scrub what the tools send back?"

Your first week

  • Get your own workspace and make one call against orcarouter/auto. You cannot sell a thing you have not used.
  • Read the six-layer flow above until you can draw it from memory. It answers most technical questions you will get.
  • Learn the difference between the guardrails engine and the firewall engine, and the two facts that differ: shadow mode and failure posture.
  • Memorize where the zero fee stops. This is the single most likely thing to embarrass you on a call.
  • Read the honest limits table twice. Knowing the edges is what makes the rest believable.
  • Pull the current pricing page yourself before your first demo. Never recite a number from this document.
  • Sit in on one call before you run one. Ask the rep what they wished they had known.
  • Find one prospect who already uses a competing gateway, and write down what they say about why. That is your real training.
